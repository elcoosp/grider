# Contributing to Grider

Thank you for your interest in improving Grider! This document describes the
workflow and the quality gates every contribution must pass.

## Development setup

You need a stable Rust toolchain (1.89 or newer, the crate MSRV):

```bash
git clone https://github.com/elcoosp/grider
cd grider
rustup component add llvm-tools-preview   # for coverage
cargo build --all-features
```

## Quality gates

Every change must keep the following commands green — CI enforces exactly these:

| Command | Purpose |
| :--- | :--- |
| `cargo fmt --all -- --check` | Consistent formatting. |
| `cargo clippy --all-targets --all-features -- -D warnings` | Lints. Pedantic clippy is configured in `Cargo.toml` `[lints]`, so pedantic warnings fail the build. |
| `cargo test --features test-utils --all-features` | Unit, integration, property and CLI tests plus doctests. |
| `cargo test --no-default-features --features test-utils` | The library must build and test without `serde`/`drawing`. |
| `cargo llvm-cov --all-features --workspace --fail-under-functions 100 --fail-under-lines 99.8 --fail-under-regions 99` | Coverage gates (see below). |
| `cargo deny check` | Advisories, license and duplicate-crate checks (`deny.toml`). |
| `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features` | Documentation builds without warnings. |

### Coverage policy

Every public function and every executable line must be exercised by the
test suite — `cargo llvm-cov show --all-features` must be fully green. CI
enforces `--fail-under-functions 100` plus line/region gates of 99.8 % / 99 %:
the few tenths below 100 % are **llvm-cov accounting artifacts**, not untested
code. When the same library is linked into many test binaries, llvm-cov keeps
count-zero duplicate records for generic instantiations whose region layout
differs between compilations; those phantom records are counted as missed even
though every real code path executes (`llvm-cov show` reports every line
covered). Do not chase those artifacts with `matches!`-based assertions or
`#[allow]` attributes — write plain `assert_eq!`/`is_err()` assertions, which
llvm-cov measures correctly.

### Rules of the codebase

- **No `allow` attributes.** If a lint fires, fix the code or, when the lint is
  provably wrong here, restructure the code so the lint does not apply. This
  keeps the linter meaningful for everyone. Lint levels live in `Cargo.toml`
  (`[lints]`), not in source annotations.
- **No `unsafe`.** Enforced by `unsafe_code = "forbid"` in `[lints]`.
- **Document all public items.** Enforced by `missing_docs = "deny"`; include
  runnable examples for anything non-trivial (doctests are executed in CI).
- **Avoid `matches!` in assertions.** llvm-cov cannot attribute execution
  counts to macro-generated match patterns, which shows up as phantom missed
  regions. Prefer `assert_eq!` against the exact error value, `is_err()` /
  `is_ok()`, or `let ... else`.
- **Keep modules focused.** One responsibility per module under `src/`
  (`config`, `detection`, `drawing`, `error`, `grid`, `lines`, `macros`, `cli`,
  `testing`). Pipeline internals belong in `detection`, not in `Grid` methods.
- **Shared fixtures** for tests and benchmarks live in `grider::testing`
  (behind the `test-utils` feature) — do not duplicate image builders.

## Commit messages

This project uses [Conventional Commits](https://www.conventionalcommits.org)
with the usual types (`feat`, `fix`, `perf`, `refactor`, `test`, `docs`, `ci`,
`chore`). The changelog is generated by [git-cliff](https://git-cliff.org) from
these messages (`cliff.toml`), and the release workflow tags versions as `vX.Y.Z`.

## Releasing

Maintainers create the release by:

1. Bumping the version in `Cargo.toml`.
2. Merging to `main` (CI must be green).
3. Pushing a tag: `git tag vX.Y.Z && git push origin vX.Y.Z`.

The `Release` workflow then verifies the tag against the crate version, runs
the test suite, generates the changelog section with git-cliff, attaches
artifacts to the GitHub release and publishes to crates.io
(needs the `CARGO_REGISTRY_TOKEN` secret).
